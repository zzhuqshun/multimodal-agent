# OCR、Qwen与工具的职责及接入顺序

状态：2026-10-12按用户最新说明确认的开发方向。OCR-VL独立解析服务已上线并通过有限接通验证；本文区分服务接通与框架/Agent实现。总体方案原文保留在[overall-plan.md](overall-plan.md)，相关依据为4.2–4.5节。

## 目标流程

材料和空白表单 → OCR或原生解析 → 带来源位置的文字片段 → Qwen理解、字段关联及下一步决策 → 程序执行工具 → 独立校验 → JSON草稿或人工复核。

| 环节 | 职责 | 输出或约束 |
| --- | --- | --- |
| OCR / 原生解析 | 扫描PDF、图片由独立文档VL解析；可直接读取的文本PDF、Excel使用原生解析 | 文档ID、片段ID、识别文字、页码/位置；VL另外保留原始结构和原图关联，不补造未返回的识别置信分数 |
| Qwen | 理解字段含义，区分实体和日期用途，关联跨材料信息，提出候选及选择下一步工具 | 引用已有片段ID和必要字符区间；不重新抄写整段原文，不生成来源坐标 |
| 工具 | 按明确参数执行日期计算、规则校验、资料确认请求及后续填报操作 | 结构化结果、错误原因、输入来源和执行记录；规则版本明确 |
| 工作流 | 执行Qwen选择的已注册工具，记录任务状态，把工具结果交回模型或进入复核 | 固定步骤由程序编排；动态判断由Qwen参与；未通过检查的字段不能进入最终填写 |
| 独立校验 / 人工复核 | 检查来源、冲突、缺失、计算与业务条件，处理识别不确定性 | 冲突和缺失保留候选、留空并提出对应请求；OCR引用一致不代表识字正确 |

例如，“访问开始日期”与“拟出境日期”需要Qwen结合上下文判断能否关联，不能只因都是日期就代填。确定出境和返程日期后，出访天数由明确规则的计算工具求得。护照号码出现两个不同值时，应保留两条来源并请求确认。

## 复用现有接口的边界

现有ParsedDocument / ParsedSegment包含文档ID、解析器版本、片段ID、text和locator，可作为OCR接入点。页面定位采用现有坐标约定；转换记录须保留，不能让模型补造坐标。原生解析和OCR产物进入相同的语义处理流程。

现有Evidence支持origin=ocr、vlm、parser及[start,end)字符区间。后续程序根据Qwen选择的片段和区间读取原文，建立证据、事实和候选；来源类型按实际识别方式记录。当前PaddleOCR-VL直接识别文字的来源应记vlm，传统OCR才记ocr，原生解析记parser；后续Qwen语义判断不改变原始来源类型。

0.1.0契约目前没有OCR置信度字段。本阶段先在独立OCR运行记录中保存引擎版本、原始结果及原图/页图关联；当前VL没有返回经校准的识字置信度，不能生成假分数，不默默增加正式接口字段。需要变更契约时再显式设计和验证。

现有PDF物理核验依赖文本层，不能直接验证无文本层扫描PDF的OCR结果。OCR接入须补充原文件哈希、页图/裁剪区域与识别记录的关联核验；识字是否正确另用独立转录答案或人工复核评测。模型不得改写原始OCR片段来使校验通过；纠错需保留独立结果和来源。

## 已有实现与差距

- 已有：受控PDF/Excel空白表解析、UTF-8参考文本读取、Qwen文字提取实验、确定性规则及可信JSON校验、独立评测、远端Qwen服务；新增独立PaddleOCR-VL-1.6完整流水线、WSL客户端、统一启停/状态入口及合成图片/扫描PDF接通验证。
- 未有：OCR产物转换为ParsedDocument、独立扫描材料准确率评测、基于片段引用的Qwen语义映射、Qwen工具选择与执行回路、表单写回。
- 现有all/document模型策略及其失败报告保留为历史基线。填报CLI当前默认仍为document策略，没有自动切换到新OCR服务。
- 当前程序在模型之后执行固定规则，不等同于Qwen已实现工具调用；服务器图片探针也不等同于OCR能力测试。

## 后续顺序与验收

1. 独立OCR最小链路已接通：PP-DocLayoutV3 + PaddleOCR-VL-1.6（0.9B），环境及权重位于/data/zhuqianshun_data/server/paddleocr-vl。相同虚构内容的PNG/无文字层扫描PDF连续5次解析通过，保留原文件哈希、页图尺寸、区域bbox、多边形、原始JSON和HTML表格。版本、故障修正、结果及限制见[OCR运行说明](ocr-runtime.md)和[真实报告](ocr-service-report.json)。这不是5份独立识别评测。
2. 下一步转换为现有ParsedDocument，保留PDF点坐标与页图像素之间的显式转换、表格行列及原始块关联；补充原图区域/识别记录物理核验。当前table的block_order为null且没有单元格bbox，应保留缺失信息。扩展独立模板、旋转/拍照/密集表格样本，分别报告文字错误、关键字段错误、结构错位和缺失；不能用下游分数代替OCR评测。
3. 再接Qwen语义判断：输入目标字段与识别片段，输出字段关联、引用及不确定原因；程序生成原文证据。评测OCR错误与语义关联错误，保留当前开发集对照，不向模型提供答案。
4. 加入最小工具执行回路：先开放日期计算、字段校验、复核请求；记录模型的工具选择、参数、工具返回及最终状态。核对错误参数、工具失败和材料冲突时能否正确停止或复核，再扩展工作流框架和填报写回。

当前15组UTF-8开发任务继续用于契约、规则与语义基线回归；它们不包含OCR样本，不能用于报告扫描材料识别成绩。
