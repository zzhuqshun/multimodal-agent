# 逐文档提取、完整性校验与有限纠错

## 模型、框架与OCR各负责什么

当前实际流程是：物理文件解析 → Qwen提取材料事实 → 程序核验证据/汇总候选/检查冲突/计算天数 → 独立评测。已有文字的PDF和Excel使用文件解析器，参考材料是UTF-8文本，均没有经过OCR。此前纯红图片探针只验证图像接口连通，不是OCR评测。

Qwen已经参与文字提取。例如护照和邀请函给出两个不同号码，模型应分别提取；程序负责看到两个候选后拒填并请求确认。模型漏掉其中一个，程序对已知候选做一致性检查仍可能误判。首轮的4个错误非空建议正说明了这个问题。

OCR将来接在文件解析位置，把扫描图片变成带页码/位置的文字；它解决看清文字的问题，后续仍需要模型理解、多来源完整性和规则校验。本轮没有安装或调用OCR，没有修改、训练或微调模型权重，也没有更换推理环境。

## 本轮实现

- 每次只给Qwen一份材料，按TaskInput原始顺序处理，随后汇总全部来源；不把多个文件直接放在一次提取请求里。
- 模型返回sources对象列表（key、segment_id、quote）和ignored片段ID列表。文档ID由当前请求上下文关联，quote仍必须由模型从原文提取。
- 使用[vLLM 0.17.1结构化输出](https://docs.vllm.ai/en/v0.17.1/features/structured_outputs/)的JSON Schema约束输出形状、允许的语义键和片段ID；quote只有字符串类型约束，没有塞入答案或预生成值。结构约束不能保证语义和完整性，程序继续单独核验。
- 每个非空片段必须有处理记录，不能既提取又ignored；已知相关标签不能忽略，已知标签不能映射到另一个语义字段。该检查依赖现有领域词表，不能证明未知标签或自然段的语义正确。
- 原文必须连续精确匹配，日期和明确姓名对应关系仍由共享规则处理；各来源保持独立候选，异常不给非空建议。
- 默认每份材料最多进行一次校验纠错。程序只把错误原因、相关片段ID和可见标签反馈给模型，请它重新输出整份材料；不生成字段值，不读答案，不修补回答，不回退到规则预测。网络、HTTP或响应封装错误不自动重试。第二次仍失败则拒绝该题。
- 两次请求、响应、错误、反馈及通过的覆盖记录都保存。被拒绝回答不会成为事实或候选，但其token消耗计入统计。缺失用量保留未知，按实际保存响应另报已知消耗。

新增21项模型流程测试，完整159项测试通过。测试验证接口和安全边界；测试通过数不是实际模型填报题数，模型成绩必须看独立评测。

## 可复现运行

默认使用逐文档且最多一次纠错：

~~~bash
cd /home/user773/multimodal_agent
set -a
source .env
set +a
.venv/bin/python -m smartfill run-model-baseline data/dev/v0.1.0
~~~

严格逐文档对照（不纠错）：

~~~bash
.venv/bin/python -m smartfill run-model-baseline data/dev/v0.1.0 --strategy document --repair-attempts 0
~~~

首轮全部材料单请求的原始策略：

~~~bash
.venv/bin/python -m smartfill run-model-baseline data/dev/v0.1.0 --strategy all
~~~

fill-model支持相同两个选项，仍需--output和--trace指定新的数据集外路径。全部预测先保存，再打开GroundTruth独立评测，0.1.0业务数据契约不变。服务仍使用同一smartfill-qwen3.5-9b，温度0、关闭thinking、4096输出上限；服务器部署参数未变。

## 本轮实验记录

3次接通试验及其失败均保留：
1. pilot-1 / grounded-document-rows-2：忽略段数组格式不符，1次请求。
2. pilot-2 / grounded-document-rows-3：模型混淆来源行的语义键与片段ID，1次请求。
3. pilot-3 / grounded-document-objects-4：结构约束生效，但出现错字段映射与处理记录重叠，2次请求。

随后冻结grounded-document-objects-5，完成严格逐文档15题对照，正式运行在runs/qwen-document-dev-v5-20261012：27次请求，15题全部被校验拒绝，0/175字段通过、0/15整题通过、没有非空建议。该结果体现更严格的拒绝行为，不能称为准确率提高。

基于这些校验错误增加一次有上限的模型纠错，处理策略标记grounded-document-repair-6，正式运行在runs/qwen-document-dev-v6-20261012。两轮均保留，未修改答案；第二轮属于开发迭代，不是独立留出成绩。系统提示词仍使用同一单文档协议，版本6另外标识有限纠错处理策略。

## 结果说明及下一步

这测的是“当前模型 + 提示词/调用流程 + 领域校验”的组合。规则版满分来自固定格式的受控开发材料；此处不能推导模型能力上限，也不能推导未知模板、真实资料或OCR准确率。服务器可以正常生成，不等于每份材料都能可靠提取。

下一步先缩小模型输出任务：让模型匹配字段与原文片段/位置，研究由程序从已验证位置取原文，减少模型重新抄写文字造成的错误；同时保留全部来源与错语义拒绝，不能用规则正确值补齐模型成绩。之后补独立模板/实体、人工核验，再接扫描件和OCR。默认CLI是严格实验模式，只输出待核验JSON草稿，不自动写回PDF/Excel。
